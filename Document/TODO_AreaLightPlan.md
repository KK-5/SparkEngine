# 面光源（LTC 矩形光）　实现方案

给光源加一种矩形面光源类型。着色用 LTC（Linearly Transformed Cosines），阴影在 P6 光追阴影之前用"矩形中心的点光源阴影"近似。

范围只有矩形光。线光源、圆盘光、带纹理的光源、光追阴影都不在本文内（§八）。

**§一是原理，独立成章，不依赖后面的实现细节，可以单独读。** §二起是本引擎的落地方案。

## 一、原理

### 1　要解决的问题

点光源着色是"一个方向上的 BRDF 值 × 辐照度"。面光源从着色点看过去是一块有面积的区域，要在它张成的球面多边形 P
上对 BRDF 积分：

```
Lo = L · ∫_P f(ωi, ωo) · cosθi dωi
```

`L` 是光源的辐亮度（假设整块光源均匀）。难点只在这个积分：每像素数值积分太贵，需要闭式解。

### 2　唯一会算的那个积分

被积函数只是 `cosθ / π`（Lambert 漫反射）时，多边形上的积分有闭式解，Lambert 在 1760 年给出：

```
E = 1/(2π) · Σ acos(pi · pj) · (normalize(pi × pj)).z
```

设想一个以**着色点**为球心、半径为 1 的球，表面法线是 z 轴。公式里的每个量：

- `pi = normalize(顶点 i − 着色点)`：从球心指向光源第 i 个顶点的单位向量，它的末端落在球面上。`pj` 是下一个顶点的。
- `acos(pi · pj)`：这两个方向的夹角。从着色点看，光源的这条边是球面上的一段大圆弧，夹角就是它的弧长。
- `normalize(pi × pj)`：着色点与这条边所在平面的法线。
- `.z`：上面那条法线在表面法线方向上的分量。
- 求和遍历光源的每条边（矩形是 4 条）。

E 是一个 0 到 1 的数，光源占满整个半球时为 1。可以手算验证：取地平线上的四个点 `(1,0,0)`、`(0,1,0)`、`(−1,0,0)`、
`(0,−1,0)` 当作一个"盖住整个半球的多边形"，每条边的夹角是 π/2，叉积都是 `(0,0,1)`，z 分量是 1，所以
`E = 1/(2π) · 4 · π/2 = 1`。

**这个公式为什么成立**，分两步。

*第一步：cosine 的积分就是投影面积（Nusselt 类比）。* 积分域是球面多边形，即光源在单位球上占的那块区域；`dω` 是这块区域
上的一小片球面的面积。把这一小片沿法线方向（z 轴）垂直压到赤道平面上：

- 一小片平面被投影到另一个平面上，面积会乘上两个平面夹角的余弦，就像斜放的纸在正午阳光下的影子比纸小。
- 球面上这一小片自己的朝向是它所在的半径方向，与 z 轴的夹角正是 θ。
- 所以它的投影面积是 `cosθ · dω`，正好是被积函数（差一个 1/π）。

把所有小片加起来：`∫ cosθ dω` = 球面多边形在赤道圆盘上的投影面积。圆盘半径是 1、面积是 π，所以除以 π 后得到的是
"投影占了圆盘的几分之几"。球顶的小片是平放的，投影不缩小；地平线附近的小片几乎竖着，投影成一条细缝 —— 这就是
掠射方向的光贡献小。

*第二步：投影面积可以沿边求和。* 从球心向每个顶点连线，每条边和球心围成一个扇形（单位圆盘上的一块"披萨"）：

- 扇形是平的，圆心角是 `θ = acos(pi · pj)`，半径是 1，面积是 `θ/2`；
- 它所在平面的法线是 `n = normalize(pi × pj)`，按第一步的道理，它投影到赤道面后的面积是 `θ/2 · n.z`；
- 投影后，这块扇形正好是"圆盘中心到这条边的投影"之间的区域。

把每条边的扇形投影面积带符号加起来，就是整个多边形的投影面积 —— 和"用原点到各边的三角形面积之和求多边形面积"
是同一个做法，多边形外面的部分正负相消。除以 π：

```
E = 1/π · Σ θ/2 · n.z = 1/(2π) · Σ acos(pi · pj) · (normalize(pi × pj)).z
```

公式只在多边形**完全位于上半球**时成立（下半球的 cosine 应被钳为 0，而公式不会钳），所以运行时要先裁剪（§一.8）。

去掉 `.z` 得到一个向量 `F`，叫 vector form factor（向量辐照度），`E = F.z`。它的方向大致指向光源的"重心"，
无裁剪近似与带纹理的光源都会用到它。

### 3　线性变换的 cosine

§一.2 给了一个工具：任意多边形上 `cosθ/π` 的积分可以精确算出来。GGX 没有这样的闭式解。接下来的全部工作，是把 GGX
的积分变成这个工具能处理的形式。

**两个被积函数是同一类东西。** 它们都是"每个方向一个权重"的函数，在球面上都是一个波瓣，只是形状不同：

| | 被积函数 | 在球面上的样子 |
|---|---|---|
| 已经会算的 | `cosθ / π` | 以法线为中心的一个胖波瓣，形状固定 |
| 想要算的 | `GGX 的 BRDF × cosθ` | 以反射方向为中心的波瓣，胖瘦与歪斜随粗糙度、视角变化 |

所以问题可以换个说法：能不能把 cosine 这个固定的波瓣，通过某种变形，变成 GGX 波瓣的样子？这种变形要满足两个要求，
它们由不同的东西保证：

| 要求 | 由什么保证 |
|---|---|
| 变形后光源还是多边形（工具只认多边形） | 只用线性变换。**任何** 3×3 矩阵都满足，不需要拟合 |
| 变形出的波瓣像 GGX | 拟合：在所有矩阵里找最像的那个（§一.5） |

顺序是：先决定只在线性变换里找，再在其中挑最像 GGX 的。单个 cosine 形状固定，拟合不了 GGX；可用的是它经线性变换
生成的**一整族**波瓣。

**变形一个分布是什么意思。** 把 cosine 分布 `Do(ω) = max(0, ω.z) / π` 想成单位半球上的一团采样点，顶部密、边缘疏。
对每个点做两步：

1. 当作 3D 向量乘上一个 3×3 矩阵 M；
2. 重新归一化，拉回球面。

这团点的新疏密就是一个新分布 D。3×3 矩阵能表示除平移以外的所有线性形变（方向本来也没有平移可言），不同分量对应不同的
形变：

| M 的形式 | 点云的变化 | 对应的 BRDF 特征 |
|---|---|---|
| `diag(a, a, 1)`，a < 1 | x、y 被压缩，点向 z 轴聚拢 | 波瓣变窄，即粗糙度变低 |
| x 与 y 缩放不同 | 点云变成椭圆形 | 掠射角时高光被拉长 |
| 带 x-z 剪切项 | 点云整体歪向一侧 | 波瓣偏离法线，指向反射方向 |

因为第 2 步要归一化，矩阵整体放大或缩小不改变任何方向，这个自由度是多余的。这是表里每个矩阵只存 4 个数的原因之一
（§一.5）。

**变形前后什么变、什么不变。** 设点云有 1000 个点：

- **整个球面上的总量不变。** 矩阵只是把点挪了位置，没有增减，所以 D 在整个球面上的积分仍是 1。后果是：D 只学到了 GGX
  的**形状**，没学到它的**总量**（GGX 的 BRDF × cosθ 积分不是 1，还带 Fresnel），总量要另外乘一个系数补回来（§一.7）。
- **光源那块区域上的值会变。** 光源多边形在球面上占一块固定区域，变形前也许有 50 个点落在里面，变形后是 300 个。这个
  变化正是要的：它反映的是"GGX 波瓣有多少落在光源上"。
- **点和区域一起变，值不变。** 这是下一节的内容，也是整个方法的关键。

**D 的显式写法。** 密度可以写出来，后面那项是变换的雅可比：

```
D(ω) = Do(ωo) · |M⁻¹| / ‖M⁻¹ω‖³        其中 ωo = normalize(M⁻¹ω)
```

这个式子只在离线拟合时用来求值（拿它和 GGX 比较），运行时用不到。

### 4　为什么积分可以搬到光源上

"D 在光源多边形 P 上的积分"就是变形后的点有多大比例落在 P 张成的锥体里。

一个变形后的点 `M·ωo` 落在 P 的锥体里，等价于它的原始点 `ωo` 落在 `M⁻¹·P` 的锥体里。所以：

```
变形后的点落在 P 里的比例  =  原始 cosine 点落在 M⁻¹P 里的比例
∫_P D(ω) dω               =  ∫_{M⁻¹P} Do(ωo) dωo
```

这就是积分换元，雅可比正好消掉。右边是 §一.2 那个会算的积分。

要让"变换光源"落到"只变换 4 个顶点"上，还需要两个事实：

- 归一化不改变一个方向属于哪个锥体，所以可以不管它，直接对顶点位置乘 M⁻¹。
- 多边形的一条边和着色点构成一个过原点的平面，线性变换后仍是过原点的平面。所以多边形变换后还是多边形，顶点对应顶点。

**直观理解**：不去扭曲波瓣，而是把世界反向扭曲，让 GGX 波瓣看起来变回 cosine，光源跟着一起变形。以低粗糙度为例，
M 是 `diag(a, a, 1)`、a 很小，则 `M⁻¹ = diag(1/a, 1/a, 1)`，光源顶点的 x、y 被放大很多倍：

- 光源在波瓣轴线上：放大后盖住半球顶部的大片区域，cosine 积分值大 —— 高光很亮。
- 光源偏离轴线：被推到地平线附近，那里 cosine 权重接近 0，积分值小 —— 高光之外几乎没有贡献。

这正是窄波瓣应有的表现，而算的始终是变形后的多边形上的 cosine 积分。

### 5　离线拟合与两张表

M 不是一个固定矩阵。它依赖两个量，离线各取 64 个采样，每组拟合一个 M，存成 64×64 的表：

- **粗糙度**：决定波瓣胖瘦。
- **视角 θv**（即 NoV）：决定波瓣的偏斜与拉长。

M **不依赖**的量，以及它们为什么不用进表：

| 量 | 原因 |
|---|---|
| 光源的位置、形状、大小 | M 只描述 BRDF 波瓣，光源是被它变换的对象 |
| N 的朝向、V 的方位角 | 运行时建局部基：N 为 z 轴，V 落在 x-z 平面，两者被基吸收 |
| F0 / 材质颜色 | Fresnel 被拆出去，放在第二张表里（§一.7） |

表只有两维，前提是 BRDF 各向同性。

**表是怎么算出来的**（上游 `fit/fitLTC.cpp`、`fit/LTC.h`）。对 64×64 个（粗糙度，视角）组合各做一遍：

1. **积分出三个量**（对 BRDF 做 32×32 个重要性采样，不涉及拟合）：
   - `norm`：F = 1 时 BRDF × cosθ 的积分，直接进 `ltc_2.x`；
   - `fresnel`：同一积分乘 `(1 − VoH)^5`，直接进 `ltc_2.y`；
   - 波瓣的平均方向。
2. **定旋转**：`M = [X Y Z] · [[m11, 0, m13], [0, m22, 0], [0, 0, 1]]`。`[X Y Z]` 把 z 轴转到上一步的平均方向（在 x-z 平面内），
   是直接算出来的，不参与优化。
3. **拟合剩下的三个数**：`m11`、`m22` 是两个方向的缩放，`m13` 是剪切。用 Nelder-Mead（不需要导数的单纯形搜索）调这三个数，
   让 LTC 与 `GGX · G2 / (4·NoV)`（即 F = 1 的 BRDF × cosθ）的差最小。正视（θ = 0）时波瓣关于法线对称，只调 `m11` 一个数。
4. **求逆、归一化、存表**：对 M 求逆，除以中间元素，存 4 个非平凡元素。

两个细节解释了表的性质：

- **误差度量是差的三次方**（在 LTC 与 BRDF 两边各采样，按 MIS 加权）。三次方偏重峰值，所以峰拟合得准、尾部拟合得差
  （§六的数值对照里能看到）。
- **初值取相邻格子的结果**：粗糙度从 1 往 0 扫，视角从正视往掠射扫，每格从上一格的解出发。粗糙度 1、正视处从单位阵
  出发（那里波瓣本来就接近 cosine）。这让搜索稳定，也让表在相邻纹素间连续，可以双线性插值。

**两张表的内容**（上游 `packTab`）：

| 表 | 通道 | 内容 |
|---|---|---|
| `ltc_1` | xyzw | M⁻¹ 的 4 个非平凡元素（先除以中间元素 `M⁻¹[1][1]` 归一化，整体缩放不影响方向） |
| `ltc_2` | x | `norm`：F = 1 时 BRDF × cosθ 在半球上的积分（方向反照率） |
| | y | `fresnel`：同一积分再乘 `(1 − VoH)^5` |
| | z | 未使用 |
| | w | 球体的地平线裁剪表（§一.8 的无裁剪近似用，**参数化与前三个通道不同**） |

**参数化**：`uv = (roughness, sqrt(1 − NoV))`，再做 `uv · 63/64 + 0.5/64` 对齐到纹素中心。v 轴取平方根是为了在掠射角处
多分配采样。

### 6　运行时流程

对每个像素、每盏矩形光：

1. **建局部基**：`T1 = normalize(V − N·dot(V, N))`，`T2 = cross(N, T1)`。在这个基里 N 是 z 轴，V 在 x-z 平面内。
2. **查表**：用 `(roughness, sqrt(1 − NoV))` 采 `ltc_1`，组出 M⁻¹。
3. **变换顶点**：光源 4 个顶点减去着色点位置，转到局部基，再乘 M⁻¹。
4. **裁剪**：裁掉地平线以下（z < 0）的部分，四边形可能变成 3 到 5 个顶点。
5. **边积分**：顶点归一化到单位球，逐边套 §一.2 的公式，得到 `E_spec`。
6. **幅值与 Fresnel**：`E_spec` 乘上 `ltc_2` 给出的系数（§一.7）。
7. **漫反射**：M⁻¹ 换成单位阵，重复 3 到 5，得到 `E_diff`。
8. **合成**：`Lo = L · (diffuseColor · E_diff + specular · E_spec)`。

一盏矩形光每像素是两次多边形积分。

**边积分的数值处理**：公式里的 `acos(pi · pj) / sin(θ)`（叉积未归一化时出现）在小夹角下精度差，会出条带。上游用一个
有理多项式拟合 `θ / sinθ`，并把 `1/(2π)` 折进系数里，见 `IntegrateEdgeVec`。照搬即可，不要换回 `acos`。

### 7　幅值与 Fresnel

**为什么要补。** `E_spec` 是"波瓣有多大比例落在光源上"，是个 0 到 1 的比例。LTC 的波瓣总量恒为 1（§一.3），而真实的
BRDF × cosθ 在半球上的总量不是 1。所以要乘上真实的总量：

```
∫_光源 BRDF·cosθ  ≈  (BRDF·cosθ 在半球上的总量) × E_spec
```

**总量为什么不是 1。** 两个原因，分开处理：

- **遮蔽。** 微表面互相遮挡，一部分光出不来，表面越粗糙损失越多。不看 Fresnel（令 F = 1）时的总量记作 `norm`。
- **Fresnel。** 反射率随角度变，还取决于材质的 F0。

**Fresnel 怎么进表。** F0 是材质参数，还是 RGB 三个通道，不能当作表的一个维度。好在 Schlick 近似对 F0 是线性的，可以
把 F0 提到积分外面。记 `w = D·G2 / (4·NoV)`（F = 1 的 BRDF × cosθ）：

```
F = F0 + (1 − F0)·(1 − VoH)^5

∫ w·F  =  F0 · ∫ w  +  (1 − F0) · ∫ w·(1 − VoH)^5
       =  F0 · norm  +  (1 − F0) · fresnel
```

两个积分都与 F0 无关，只取决于粗糙度与视角，可以预先算好：`norm` 存在 `ltc_2.x`，`fresnel` 存在 `ltc_2.y`。运行时：

```
specular = (F0 · ltc_2.x + (1 − F0) · ltc_2.y) × E_spec
```

两个极端可以帮助理解：F0 = 1（理想的白色金属）时系数就是 `norm`；F0 = 0 时系数是 `fresnel`，只剩掠射角的那点反射。

**几个实际的值**（读自表，行换算成视角）：

| 粗糙度 | 视角 | `norm` | `fresnel` |
|---|---|---|---|
| 0 | 0° | 1.000 | 0.000 |
| 0.5 | 0° | 0.912 | 0.000 |
| 1 | 0° | 0.307 | 0.000 |
| 0.5 | 42° | 0.882 | 0.003 |
| 0.06 | 65° | 1.000 | 0.066 |
| 1 | 90° | 0.932 | 0.047 |

`norm` 随粗糙度下降（最粗糙、正视时只剩 31%，这是单次散射微表面模型自身的能量损失，点光源用的是同一个 BRDF，损失
相同）；`fresnel` 正视时几乎为 0，越掠射越大。

**这里藏着一个近似。** 上面乘的是**整个波瓣**的平均 Fresnel，而光源只盖住波瓣的一部分。Fresnel 在波瓣内部并不均匀
（朝掠射方向的那一侧更大），光源盖住哪一侧，真实的加权值就偏向哪一侧。F0 低、视角偏掠射、光源只盖住波瓣一侧时误差
最明显（§六的数值对照）。

**与 IBL 的关系。** 这与 split-sum 是同一个思路、同一个量：`g_BRDFLut` 的 `(scale, bias)` 满足 `scale = norm − fresnel`、
`bias = fresnel`，代进去 `F0·scale + bias` 与上式相等。两张表独立烘焙、参数化不同，数值上应当吻合，可以用来互相校验。

### 8　地平线裁剪

Lambert 公式要求多边形在上半球，所以变换后的多边形要先裁到 z > 0。两种做法：

- **精确裁剪**（`ClipQuadToHorizon`）：按 4 个顶点各自在地平线上下分 16 种情况，输出 3 到 5 个顶点。结果精确，分支多。
- **无裁剪近似**（Hill & Heitz 2016）：不裁剪，直接算向量 `F`；把光源当作一个张角与 `|F|` 对应、方向为 `F` 的球，
  查一张预计算的"球体被地平线遮挡后的 form factor"表（`ltc_2.w`，uv 为 `(F.z/|F| · 0.5 + 0.5, |F|)`）作修正。分支少，
  光源穿过地平线时有少量误差。

### 9　这个方法是怎么推出来的

从约束倒推，每一步的选择余地都很小：

1. **起点是唯一会算的积分**（§一.2）。问题反过来问：还有哪些积分能化归成它？
2. **化归积分的标准手段是换元。** 换元后积分域变形，而 Lambert 公式要求积分域仍是多边形，即大圆弧必须映射成大圆弧。
   大圆弧是过原点的平面与球面的交线；能把过原点的平面映射成过原点平面的变换，基本只有线性变换。所以"线性"是被
   "保住多边形"这个约束逼出来的。
3. **剩下的问题是这个候选够不够用。** 3×3 矩阵的自由度是缩放、各向异性缩放、剪切，正好对应 GGX 波瓣的胖瘦、掠射角
   拉长、偏斜。这一步没有理论保证，是拟合出来看效果的 —— 所以 LTC 是近似而不是精确解。
4. **与重要性采样的关系**：逆 CDF 采样是把均匀分布扭曲成目标分布；LTC 是同一件事反过来用，把扭曲施加到积分域上，
   并限定扭曲必须是线性的。

### 10　LTC 不解决的事

- **阴影**：LTC 算的是无遮挡积分。遮挡是另外乘上去的一个标量可见性（§五）。
- **带纹理的光源**：公式假设辐亮度均匀。带纹理只能近似：用 `F` 的方向与光源平面求交得到 UV，按距离与面积选预滤波 mip。
- **其它形状**：原始论文只覆盖多边形。线光源、圆盘 / 椭圆是 2017 年的后续工作，积分公式不同（上游有 `ltc_line.fs`、
  `ltc_disk.fs`）。
- **各向异性 GGX**：表的维度要涨到四维，原版不支持。
- **拟合误差**：高粗糙度加掠射角时，拟合出的波瓣与真实 GGX 偏差最大。

## 二、数据层（步骤 1）

沿现有链路逐层加：`LightComponent → LightRenderData → LightData → shader`。

**组件**（`Feature/Light/Components.h`、`Reflect.h`）：`LightType` 加 `Rect = 3`；`LightComponent` 加 `m_width`、`m_height`
（世界单位，缩放前）。沿用"各类型字段平铺"的现状。

**LightSystem**（`LightSystem.cpp`）：矩形需要完整朝向，现在只取了世界矩阵的第 2 列。对矩形光：

- `forward = normalize(col2)`，与其它类型一致；
- `right = normalize(col0 − forward · dot(col0, forward))`，正交化，丢弃剪切；
- `halfWidth = 0.5 · m_width · |col0|`，`halfHeight = 0.5 · m_height · |col1|`，各自钳到下限；
- `m_intensity` 写入换算后的辐亮度：`lc.m_intensity / (4 · halfWidth · halfHeight)`（D3）；
- `LightBounds` 为 `Sphere{ position, range }`。现在的 `ResolveBounds` 把非 Point 一律当锥体，矩形要有自己的分支。

up 轴不存、不传：shader 里 `up = cross(direction, right)`。这样镜像缩放（负的 x 缩放）不会翻转顶点绕序。

**GPU 记录**（`Binding/Scene/LightData.h` 与 `Shaders/LightData.hlsli`，两侧同步，`static_assert` 改为 96）：

```hlsl
struct LightData   // 96 bytes
{
    float3 direction; float intensity;       // rect: intensity 是辐亮度
    float3 color;     uint  type;            // 3 = rect
    float3 position;  float invRange;
    float  cosInner;  float cosOuter;  int shadowIndex; uint shadowFaceCount;
    float3 right;     int   shadowMaskIndex; // rect: 单位 right 轴
    float  halfWidth; float halfHeight; uint padding0; uint padding1;
};
```

`intensity` 是唯一含义随类型变的字段：换算留在上游，`SceneBindingSystem::PackLightData` 仍是纯拷贝。

## 三、LUT（步骤 2）

**导入工具**：`SandBox/Program/RHI/LTCLutGen.cpp`，仿 `BRDFLutGen`，但不需要 RHI：读上游两个 DDS（128 字节头 + 64×64×8
字节的 `RGBA16F`），原样写成 `Engine/Asset/Image/LTC1.ktx2`、`LTC2.ktx2`（`R16G16B16A16_FLOAT`，单 mip），再经 AssetManager
读回逐字节比对。上游的 DDS 不进仓库，工具从命令行参数取路径。

行序不用翻：列是粗糙度、行是视角（第 t 行对应 `v = t/63`），DDS 与 D3D 的第 0 行都是 v = 0。工具里打印几个点作检查，
写错轴向在别处是静默的。下面的值读自上游的 DDS：

| 纹素（列 = 粗糙度，行 = 视角） | `ltc_1` | `ltc_2.x` |
|---|---|---|
| (0, 0)　光滑、正视 | `(1, 0, 0, 0)` | 1 |
| (32, 0) | `(1, 0, 0, 0.496)` | 0.912 |
| (63, 0)　最粗糙、正视 | `(1, 0, 0, 1.128)` | 0.307 |
| (32, 32) | `(0.626, −0.220, 0.532, 0.312)` | 0.882 |

- 第 0 行（正视）波瓣关于法线对称，所以 `ltc_1` 恒为 `(1, 0, 0, w)`，w 随粗糙度单调增；轴向弄反时这一行会出现非零的 y、z。
- (63, 0) 处的 0.307 有闭式解 `1 − ln 2`（α = 1、正视时 `D = 1/π`、`ΛV = 0`，积分可以手算），可以确认上游用的就是高度相关
  Smith。`g_BRDFLut` 在 `(NoV = 1, roughness = 1)` 处的 `scale + bias` 应是同一个数（§一.7）。

**绑定**（`SceneBindingSystem`、`SceneBindings.hlsli`）：`g_LTC1`、`g_LTC2` 放进 space0。加载与
`RegisterStaticShaderRead` 照 `CreateBRDFLut` / `BindEnvironmentIBL` 的写法，但走一条**不依赖天空盒**的路径：

- 两张表就绪后每帧绑定，并写 `g_AreaLightLutReady`（D11）。
- **采样器也要挪**：`g_IBLSampler` 现在在 `BindEnvironmentIBL` 的门后面才设置，没有天空盒时是未设置的。LTC 复用这个
  线性 clamp 采样器，所以它的设置要移到无条件路径。
- 新资源要同时加进 `SceneBindingsReflect.hlsl` 和 `SpaceZeroKeepAlive`，漏任何一处都是静默错位
  （`TODO_StructureAlignPlan.md` 记的那笔欠账）。

## 四、着色（步骤 3）

**`Shaders/Lib/LTC.hlsli`**：纯库，表与采样器由调用方传入，同 `EnvBRDFLut` 的约定（BRDF 头文件不把 scene bindings 拖进
每个包含它的 shader）。内容是 `IntegrateEdgeVec`、`ClipQuadToHorizon`、`LTC_Evaluate` 的移植，加查表与组 M⁻¹。

**`Lights.hlsl`**：循环里按 `type` 分支。矩形光不走 `EvaluateLight` + `EvaluateBRDF`：那一对接口是"一个 L 加一个 radiance"，
LTC 没有单一的 L，直接输出积分后的漫反射与高光。ShadowMask 那一乘不变。

- **range 窗口**：与点光源同一个窗口函数，距离取到矩形中心的距离。LTC 自带距离衰减，窗口只负责让影响范围有界。
- **提前退出**：着色点在光源背面（`dot(P − position, direction) <= 0`）或超出 range 时跳过，不进 LTC。

**移植时会出错的三处**：

- **矩阵行列约定。** GLSL 的 `mat3(a, b, c)` 按列构造，HLSL 的 `float3x3(a, b, c)` 按行。配合 `mul(M, v)`：
  - M⁻¹ 是 `float3x3(t1.x, 0, t1.z,   0, 1, 0,   t1.y, 0, t1.w)`（上游写作 `mat3(vec3(t1.x, 0, t1.y), …)`，y 与 z 的位置相反）；
  - 世界到局部基是 `float3x3(T1, T2, N)`，**不要**再 `transpose`（上游的 `transpose(mat3(T1, T2, N))` 是同一个矩阵）。
- **顶点绕序决定哪一面发光。** 上游顶点序为 `(−x,−y) (+x,−y) (+x,+y) (−x,+y)` 时，发光面朝向 `−cross(dirx, diry)`。
  本引擎光沿 `+forward = +cross(right, up)` 发射，方向相反，所以取 `dirx = right`、`diry = −up`。绕序错了整盏灯全黑。
- **NoV 的钳制。** 查表用 `saturate(dot(N, V))`；V 与 N 平行时 `T1` 的归一化是 0/0，需要兜底。

## 五、阴影（步骤 4）

**现在的做法**（`View/ShadowViewSystem.cpp`）：`ShadowFaceCount` 对矩形返回 6，`Activate` 里矩形走 `WritePointFaceView`。
`ShadowProjection.hlsl` 按 `shadowFaceCount > 1` 选 cube face，不用改。

矩形只向前半球发光，整个位于发光平面背后的 face 不需要 tile：face 远端 4 个角点都满足
`dot(corner − position, forward) <= 0` 时，从 `faceMask` 里去掉它。没有 tile 的 face 仍占着行、读作不遮挡，这是现有机制。

**这个近似错在哪**：它回答的是"能否看到光源中心"，真实阴影是"光源面积有多大比例可见"。

- 整块光源可见或整块被挡的地方，两者相同。
- 半影处真实值是渐变，这里是一条硬边（位置大致在真实半影中间），PCF 只把它模糊固定几个 texel。
- 误差的大小就是真实半影的宽度：`光源尺寸 × (接收面到遮挡物的距离) / (遮挡物到光源的距离)`。
- 半影窄时只是效果差；遮挡物比光源小时是性质错误（真实情况没有本影，这里是一条清晰的黑影）。

光栅 atlas 给不出随距离变化的半影：滤波宽度被有意限定为 3 / 5 / 7 texel 的枚举（点光源各面的 fov 要按最宽 tap 留边），
PCSS 需要的可变半径与它冲突。

**P6 之后**：ShadowMask 的来源换成光追阴影 + SIGMA。届时两件事：

- `ShadowMaskSystem` 现在只给持有 `ShadowViewRefs`（atlas 行）的光源发槽位，光追阴影的光源没有 atlas 视图，要解耦。
- 标量遮罩乘 LTC 默认了"可见性"与"BRDF × 辐亮度"在光源面上不相关。低粗糙度高光下有偏差，可用 ratio estimator
  （§一.11 的 I3D 2018）：`LTC 无阴影结果 × 降噪(随机采样的有阴影 / 随机采样的无阴影)`。

## 六、验证（步骤 5）

### 已做：离线数值对照

把 `Lib/LTC.hlsli` 与 `EvaluateRectLight` 逐行转写成 Python，读同一份表，与"引擎的 BRDF（`D_GGX · V_SmithGGXCorrelated ·
F_Schlick`）在矩形上的数值积分"对比。脚本是一次性的，没有进仓库。它验证的是公式、约定与表的读法，不是 HLSL 文本本身，
也不涉及引擎里的数据链路。

| 项 | 结果 |
|---|---|
| 漫反射（各种朝向、倾斜法线、V 与 N 平行、灯穿过地平线） | 与数值积分一致，差异在 0.1% 以内 |
| 背面 | 0 |
| 极小矩形对比同强度点光源 | 一致（D3 的换算） |
| 高光波瓣逐方向对比 | 镜面方向附近 LTC 与 GGX 的比值为 1.00（三组粗糙度 / 视角），峰的位置与高度都对上 |
| 把 M⁻¹ 故意转置 | 高光变成 0 或数倍，说明现在的行列约定是对的那个 |
| 高光积分值（灯盖住波瓣主体） | 误差多在 ±1% 到 ±9% |
| 高光积分值（灯只蹭到波瓣尾部） | 误差可到 20% 到 30% |

最后一行是 LTC 本身的近似误差，不是移植问题，来源有两个：

- **尾部拟合差**：拟合的误差度量偏重峰值，波瓣尾部（尤其背向散射一侧与掠射视角的侧向）可以差 20% 以上，背向一侧
  LTC 直接是 0。尾部的绝对值很小，画面上是高光外围的光晕略有出入。
- **Fresnel 取的是整个波瓣的平均**（§一.7）：F0 很低（非金属）且视角偏掠射时，Fresnel 在波瓣内变化大，灯只盖住波瓣
  一侧时平均值不准。
